\subsection{\redd{PART \romannum{2}} - The Path-sensitive Reachability-bound Analysis}
\label{sec:intro-methodology-reachability}
In \redd{PART \romannum{2}},
the property I look into is \emph{the number of times a given location inside a procedure is visited during the program
execution}.
Specifically, I want to estimate an upper bound on this property for each program location, namely the \emph{reachability-bound}.
Existing methods from different areas have different limitations in computing precise \emph{reachability-bound}s for different program locations.
I mainly studied four different methodologies.
Below, I summarize the limitations of each of them
and then introduce how I leverage these limitations in the proposed approach.

\subsubsection{Program Abstraction}
\paragraph{Existing Techniques and Limitations.}
The program abstraction techniques are widely used in the program analysis area to precisely summarize the key property of the program. They are usually based on some specific abstract interpretation models as introduced in Section~\ref{sec:intro-methodology-adapt}.
In analyzing the loop bounds, the unified lattice model in~\cite{CousotH78}, polyhedra in~\cite{CousotC77}, and octagons in~\cite{Mine06} are used in~\cite{GulwaniZ10} to summarize the loop transition and generate the transition system.

In the new method, I extend the difference constraint-based program abstraction algorithm in~\cite{SinnZV17} and~\cite{SinnZV14} with boolean expression abstraction to generate the abstract transition graph

\subsubsection{Loop Summarization and Path Refinement}
\paragraph{Existing Techniques and Limitations.}
One kind of loop bound analysis through loop summarization and path refinement seeks precise loop path representation such as~\cite{ManoliosV06, BalakrishnanSIG09, SharmaDDA11, Flores-MontoyaH14, HumenbergerJK18, CyphertBKR19}, and compute loop bound over accurate loop summarization such as~\cite{GulwaniJK09, ZulegerGSV11}.
They mainly focus on summarizing the loop path and computing the interleaving between paths, as well as computing the precise bound considering the interleaving. However, composing the bound between nested loops
need to recursively unroll the nested loops and compute the interleaving between unrolled paths.
These operations are usually inefficient and non-terminating.
\paragraph{Proposed Method.}

It computes the refined program over the abstract transition graph generated above.

\subsubsection{Amortized Complexity Analysis through Ranking Function}
\paragraph{Existing Techniques and Limitations.}
This kind of method is originated from Tarjan's influential paper~\cite{PotechinP17}.
They are usually combined with \emph{ranking function} estimation method in~\cite{BradleyMS05} such as the works in~\cite{ZulegerGSV11, SinnZV14, SinnZV17, LuCT21, AliasDFG10}.
Indeed, using techniques like ranking functions, counter increments, difference constraints, etc.
one can estimate

However, these techniques are designed to capture the worst-case or overall complexity, and again they may over-approximate the reachability-bounds of some locations.
When there are multiple paths and the path interleaving affects the loop execution, the over-approximation is more evident.

In the new approach, I use the ranking function estimation-based \emph{amortized complexity analysis} techniques
by alternatively computing the bound on each ranking function and transition edge.
To overcome the over-approximation limitations in multi-paths loops, I deploy the loop path refinement technique and perform the \emph{amortized complexity analysis} over the refined programs.
In this sense, I estimate the ranking function in a path-sensitive manner.

\subsubsection{Reachability-bound Computation}
\paragraph{Existing Techniques and Limitations.}
Existing static analysis techniques cannot compute the \emph{reachability-bound} on a given program control location directly or path-sensitively.
Most of them focus only on the \emph{quantitative} sub-property, specifically the overall program execution complexity.
For example,~\cite{GulwaniZ10}
give a two-step solution by combining program abstract and proof-rules-based bound computation.
But it does not compute the \emph{reachability-bound} precisely for every control location.
% , which is the \emph{reachability} perspective of this property.
Instead, they only compute the complexity bounds for the overall loop and over-approximate for different locations using this bound,
which is loose especially when there are multipath loops.
In this sense, they only estimate the \emph{quantitative} sub-property and lose the \emph{reachability} perspective of the \emph{reachability-bound}.
Techniques in program complexity analysis in the work~\cite{GustafssonEL05,HumenbergerJK18} 
or worst-case resource cost analysis in
~\cite{BrockschmidtEFFG16,AlbertAGP08,AliasDFG10,Flores-MontoyaH14} can be repurposed to estimate similar quantities such as the
bounds on loop iterations, execution time, etc.
While these quantities focus only on 
the overall complexity,
none of them compute the \emph{reachability-bound} on a given program control location directly or path-sensitively.
For the same reason, these methods also over-approximate the \emph{reachability-bound}
by using the overall quantity.

\paragraph{Proposed Method.}
To overcome these limitations, 
I design
our algorithm
over the abstract transition graph and effectively use the \emph{amortized complexity analysis} and \emph{loop summarization-based multipath refinement} techniques in the first step.
In this way, the new algorithm mitigates the limitations faced by each technique individually. 
Then, I introduce two novel quantities,
the \emph{path reachability-bound} and \emph{loop reachability-bound}.
% They are two main novelties of our new path-sensitive reachability-bound algorithm built on traditional methods.
The first one -- \emph{path reachability-bound} -- bounds the evaluation times of each loop-free and interleave-free path in a refined program, and the second one -- \emph{loop reachability-bound} -- bounds the number of iterations of an outer loop w.r.t. an inner loop, counting only the iterations when the inner loop is ``entered''. 
I present algorithms for estimating these two quantities. By using them, I can then 
%Section~\ref{sec:looprb} and~\ref{sec:pathrb} 
compute the \emph{reachability-bound} for each program point in a path-sensitive way.
To this end, the new methodology studies both the \emph{reachability} and the \emph{quantitative} perspectives and
analyzes the \emph{reachability-bound} in a higher granularity.
