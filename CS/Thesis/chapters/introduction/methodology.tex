\subsubsection{Language Models}
\label{sec:intro-methodology-adapt-language}
\paragraph{Existing Programming Languages and The Limitations}
Most of the data analysis algorithms are implemented in Python equipped with the panda, numpy, TensorFlow, etc. libraries for database access and data training computation, 
or in C with some external database access libraries, etc.
These languages and external libraries are mainly focusing on the efficiency and scalable of the programs that implement these algorithms.
None of them takes care of the generalization error of the corresponding algorithms that these programs implemented.
% In terms of adaptivity, none of them take care of this property w.r.t. these data analysis algorithms implemented.
In this sense, analyzing the \emph{adaptivity} as a program property in order to control generalization error
is difficult based on existing programming languages.
% However, the variety of the external API makes the formalization of data analysis algorithms and their adaptivity property over these languages difficult.

\paragraph{Our Language Model}
We identify some data analysis models which are usually used as the base of data analysis algorithms.
Based on these models, we design a simple but scalable language model based on standard while language that can be used to implement these algorithms and formalize
the \emph{adaptivity}, named {\tt QWhile}.
It is a standard while language enriched with the query request command and labels on each program command. 


\subsubsection{Program Property Formalization}
\label{sec:intro-methodology-adapt-formalization}
As discussed in the abstract and introduction sections, this \emph{adaptivity} is commonly used as an intuitive concept in the data analysis area.
To study it as a program property, we need to have 
% a formal 
model where 
this concept is formally defined as a program property, specifically a \emph{quantitative-reachability} property.
There are many ways to formally define a program's conceptual property. However, they all have difficulties in capturing its two perspectives sub-properties, the \emph{quantitative} and \emph{reachability}. 
We summarize some existing formalization methods with their limitations and then introduce how we formalize this concept.

\paragraph{Existing Methodology and The Limitations}
The \emph{abstract interpretation} based methodology which is originated from Cousot's influential paper~\cite{CousotH78, CousotC77} and intensively developed in~\cite{Mine06, ZanioliC11, MastroeniZ17, KincaidCBR18, Cousot19a, JanaHAGC20}, etc. This category of methods is focusing on formalizing property from the \emph{reachability} perspective,
such as the dependency relation defined in~\cite{Cousot19a}, program point reachability formalized in~\cite{MastroeniZ08}, etc.
However, they are not able to capture the \emph{quantitative} sub-property for the \emph{adaptivity}.

The \emph{execution history and program simulation}-based methodology~\cite{Israel56, Kildall73}
are also widely used in defining
and formalizing the program's properties.
However, they have the same limitation as the abstract interpretation-based methodology. It is not straightforward how to apply them to define the \emph{adaptivity} as a \emph{quantitative-reachability} property from two perspectives.

There is also purely \emph{syntactic}-based methodology originated from~\cite{Weiser84} and developed in~\cite{DenningD77} in defining a property (the data dependency relation).
However, these methods are limited to certain languages and are not easy to generalize into other language models.

%
\paragraph{New Methodology}
Because of its nature as a \emph{quantitative-reachability} property, defining \emph{adaptivity} requires us to define from both
the \emph{reachability} and the \emph{quantitative} perspectives.
Our new methodology formalizes it
% this intuitive \emph{adaptivity} as a \emph{quantitative-reachability} program property 
via a semantics-based definition as follows.
\begin{enumerate}
 \item From the \emph{reachability} perspective, our approach defines this sub-property as the \emph{data dependency} relation.
 % based on our trace-based semantics.
 % The semantics-based definition is inspired from~\cite{Cousot19a, ZanioliC11, CheneyAA11}.
 The new definition captures both the control influence and value influence between data, which are never fully captured in previous dependency relation~\cite{Cousot19a, ZanioliC11, CheneyAA11}.
 It can be used to reason about the dependency between queries.

 \item Then in terms of the \emph{quantitative}
 % sub-property, 
 we use the \emph{reachability-bound} with respect to certain data to capture it.
 We borrow the idea from the program complexity analysis works in~\cite{GulwaniJK09}, which works well in capturing the dependency depth between queries.
 
 \item With the two sub-properties defined above, we construct a dependency graph by using the
 % combining both the \emph{dependency relation} (as the graph edge) and \emph{dependency quantity} (as the vertex weight) on it. 
 \emph{data dependency} relation as the graph edge and the \emph{reachability-bound} as the vertex weight.
 In this way, we encode both of the two perspective sub-properties of the intuitive \emph{adaptivity} on this graph.
 % This dependency graph accurately reflects the two perspectives of the intuitive \emph{adaptivity}. 
 Although there are previous works designing the weighted dependency graph, none of them are able to carry both dependency and dependency depth in terms of the queries used in data analysis algorithms.
 % and apply it into analyzing the \emph{adaptivity}.
 
 \item Based on this graph, we introduce a new concept, the longest \emph{finite walk} over this graph, and the \emph{adaptivity} is defined as the length of this walk.
 To this end, we formally capture the \emph{adaptivity} as a \emph{quantitative-reachability} program property.
 % This longest \emph{finite walk} is also a novel quantity in the graph theory area that is never considered before.
 \end{enumerate}

From the high level, the \emph{adaptivity} is defined by the longest \emph{finite walk} over a dependency graph. This graph contains both
the \emph{reachability} and the \emph{quantitative} sub-properties.
None of the existing methodologies is able to capture this hyper-property as precisely as our methodology.
We present this formalization procedure in Chapter~\ref{sec:adapt-exe}.

Some existing methodologies can be the base method in analyzing it, but there are many challenges.

Both of these two kinds of analysis techniques can help to estimate the \emph{reachability} sub-property.
However, to the best of our knowledge, 
most of the existing static dependency analysis or control flow analysis techniques consider only either the value influence or control influence.
To analyze the \emph{reachability} sub-property w.r.t. the queries in the adaptive data analysis program, we need to consider both of them.

However, they are focusing on estimating the

\subsection{\redd{PART \romannum{2}} - The Path-sensitive Reachability-bound Analysis}
\label{sec:intro-methodology-reachability}

This property is a worst-case bound on the number of times a given control location 
inside a procedure is visited during the program execution.
Many works in the program analysis area develop algorithms estimating the program's loop bound or overall complexity.
However, there isn't a general analysis algorithm that solves this problem directly or path-sensitively for each program location.
Existing methods from different areas have different limitations in computing the reachability-bound.
Below we summarize some limitations of the relevant methodologies and introduce how we leverage them in our new approach.

\subsubsection{Program Abstraction}
\paragraph{Existing Techniques and Limitation.}
The program abstraction techniques are widely used in the program analysis area to precisely summarize the key property of the program. They are usually based on some specific abstract interpretation models as introduced in Section~\ref{sec:intro-methodology-adapt}.
In analyzing the loop bounds, the unified lattice model~\cite{CousotH78}, polyhedra~\cite{CousotC77}, and octagons~\cite{Mine06} are used in~\cite{GulwaniZ10} for summarize the loop transition and generating the transition system.
But none of the three abstraction models can represent the if guard in the multipath loops, and solving the transition system using these abstraction models is low-efficient. The wedge abstract developed in~\cite{KincaidCBR18} for generating the non-linear loop invariant
computing the \emph{reachability-bound} can also be used. While it only works well for the specific targeting problem, and still low-efficient or inaccuracy in summarizing the multipath loops and solving the path-sensitive \emph{reachability-bound} problem. 

\paragraph*{Our Method.}
In our algorithm, we choose to use the difference constraint-based program abstraction model combined with boolean expression abstraction to generate our abstract transition graph
% $\absG(c)$ 
for a program.
% $c$. 
Each command in the program is abstracted into an abstract transition.
% , $\absevent$.
It can represent the program loops path-sensitively which is more accurate than the state-of-art program abstraction models.
It is based on the difference constrain model in~\cite{SinnZV17} and the size change abstraction in~\cite{SinnZV14}. The efficiency also benefits from our
semantics model, which is inspired from~\cite{Cousot19a} and~\cite{Cousot19} and has similar intuition with the program model in~\cite{SinnZV17}.


\subsubsection{Amortized Complexity Analysis through Ranking Function}
\paragraph{Existing Techniques and Limitation.}
This method is originated from Tarjan's influential paper~\cite{PotechinP17} combined with \emph{ranking function} estimation from~\cite{BradleyMS05} and developed in~\cite{ZulegerGSV11, SinnZV14, SinnZV17, LuCT21, AliasDFG10}.
Indeed, using techniques like ranking functions, counter increments, difference constraints, etc.
one can estimate 
precise bounds on loop iterations and execution time,
and in turn, obtain reachability bounds for complex programs.
However, these techniques are designed to capture the worst-case or overall complexity, and again they may over-approximate the reachability-bounds of certain locations.
When there are multiple paths and the interleaving affects the loop execution, the over-approximation is more evident.

\paragraph{Our Method.}
To improve these limitations, our methodology deploys the loop path refinement technique and performs the \emph{amortized complexity analysis} over the refined programs.
The \emph{amortized complexity analysis} techniques we use is through the ranking function 
% $\locbound(\absevent, c)$ 
estimation
% $\absevent$, 
and alternatively computing the bound on each ranking function and transition edge.
It is also efficient and accurate without recursively unrolling the nested loops when composing the bound of different paths.
However, deployment of the path refinement technique has its limitation as well.

\subsubsection{Loop Summarization and Path Refinement}
\paragraph{Existing Techniques and Limitation.}
Another line of loop bound analysis through loop summarization and path refinement seeks precise loop path representation~\cite{ManoliosV06, BalakrishnanSIG09, SharmaDDA11, Flores-MontoyaH14, HumenbergerJK18, CyphertBKR19}, and compute loop bound over accurate loop summarization~\cite{GulwaniJK09, ZulegerGSV11}.
They mainly focus on summarizing the loop path and computing the interleaving between paths, as well as computing the precise bound considering the interleaving. However, composing the bound between nested loops. Recursively unrolling the nested loops and computing the interleaving between unrolled paths are heavy and non-terminating.
\paragraph{Our Method.}
Our new approach uses a lightweight path refinement algorithm adapted from~\cite{GulwaniJK09}.
It computes the refined program based on the abstract transition graph and then
effectively combines this methodology with the \emph{amortized complexity analysis} above through ranking function estimation.

\subsubsection{Reachability-bound Computation}
\paragraph{Existing Techniques and Limitation.}
As we discussed above, most of the existing static analysis methodologies cannot compute the reachability-bound on a given program control location directly or path-sensitively.
Most of them focus on one the \emph{quantitative} perspective of this property.
For example, Gulwani et. al~\cite{GulwaniZ10}
give a two-step solution by combining program abstract and proof-rules-based bound computation.
But it does not compute the \emph{reachability-bound} precisely for every control location.
% , which is the \emph{reachability} perspective of this property.
Instead, they only compute the complexity bounds for the overall loop and over-approximate for different locations using this bound,
which is loose especially when there are multipath loops.
In this sense, they only estimate the \emph{quantitative} sub-property and lose the \emph{reachability} perspective of the \emph{reachability-bound}.
Techniques in program complexity analysis~\cite{GustafssonEL05,HumenbergerJK18} 
or worst-case resource cost analysis
~\cite{BrockschmidtEFFG16,AlbertAGP08,AliasDFG10,Flores-MontoyaH14} can be repurposed to estimate similar quantities such as the
bounds on loop iterations, execution time, etc.
While these quantities focus only on 
the overall complexity,
none of them compute the reachability-bound on a given program control location directly or path-sensitively.
For the same reason, they also lose the \emph{reachability} perspective of the \emph{reachability-bound}.

\paragraph{Our Method}
To overcome these limitations, 
our algorithm is built over an abstract transition graph which effectively combines \emph{amortized complexity analysis} with \emph{loop summarization-based multipath refinement}.
This combination mitigates the limitations faced by either technique individually. 
Building on this combination, we introduce two novel quantities,
the \emph{path reachability-bound} and \emph{loop reachability-bound}.
They are the main novelty of our new path-sensitive reachability-bound algorithm built on traditional methods.
The first one bounds the evaluation times of each loop-free and interleave-free path in a refined program, and the second one bounds the number of iterations of an outer loop w.r.t. an inner loop, counting only the iterations when the inner loop is ``entered''. 
We present algorithms for estimating these two quantities. By using them we can then 
%Section~\ref{sec:looprb} and~\ref{sec:pathrb} 
compute the \emph{reachability-bound} for each program point in a path-sensitive way.
To this end, our new methodology studies both the \emph{reachability} and the \emph{quantitative} perspectives and
analyzes the \emph{reachability-bound} in a higher granularity.
