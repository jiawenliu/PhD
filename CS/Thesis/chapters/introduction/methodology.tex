There are many ways to formally define a program's conceptual property. However, they all have difficulties in capturing its two sub-properties, the \emph{quantitative} and \emph{reachability} properties. 
We summarize some existing formalization methods with their limitations and then introduce how we formalize the concept of \emph{adaptivity}.

\paragraph{Existing Formalization Methods and Limitations.}
There are mainly three kinds of methodologies in formalizing a program's property.

\emph{{Abstract Interpretation}-Based.}
The \emph{abstract interpretation}-based methods were developed in the Cousot's seminal paper~\cite{CousotH78, CousotC77}.
This category of methods is extensively developed 
in~\cite{Mine06, ZanioliC11, MastroeniZ17, KincaidCBR18, Cousot19a, JanaHAGC20}, etc. Majority of these methods are focusing on formalizing property from the \emph{reachability} perspective,
such as the dependency relation defined in~\cite{Cousot19a}, program point reachability formalized in~\cite{MastroeniZ08}, etc.
However, they are not able to capture the \emph{quantitative} sub-property of \emph{adaptivity}.

\emph{Execution History And Program Simulation-Based.} 
The \emph{execution history and program simulation}-based formalization methods by~\cite{Israel56, Kildall73}
are also widely used in defining
and formalizing the program's properties.
However, they have the same limitation as the \emph{abstract interpretation}-based methodology. It is not straightforward how to apply them to define the \emph{adaptivity}
%  as a \emph{quantitative-reachability} property from two perspectives.
involving its \emph{quantitative} and \emph{reachability} sub-properties. 

\emph{{Syntactic}-Based.} There are also some \emph{syntactic}-based formalization methods, which is originated from~\cite{Weiser84} and developed in~\cite{DenningD77}.

\paragraph{Existing Techniques and Limitations.}

\subsubsection{Reachability-bound Computation}
\paragraph{Existing Techniques and Limitations.}
Existing static analysis techniques cannot compute the \emph{reachability-bound} on a given program control location directly or path-sensitively.
Most of them focus only on the \emph{quantitative} sub-property, specifically the overall program execution complexity.
For example,~\cite{GulwaniZ10}
give a two-step solution by combining program abstract and proof-rules-based bound computation.
But it does not compute the \emph{reachability-bound} precisely for every control location.
% , which is the \emph{reachability} perspective of this property.
Instead, they only compute the complexity bounds for the overall loop and over-approximate for different locations using this bound,
which is loose especially when there are multipath loops.
In this sense, they only estimate the \emph{quantitative} sub-property and lose the \emph{reachability} perspective of the \emph{reachability-bound}.
Techniques in program complexity analysis in the work~\cite{GustafssonEL05,HumenbergerJK18} 
or worst-case resource cost analysis in
~\cite{BrockschmidtEFFG16,AlbertAGP08,AliasDFG10,Flores-MontoyaH14} can be repurposed to estimate similar quantities such as the
bounds on loop iterations, execution time, etc.
While these quantities focus only on 
the overall complexity,
none of them compute the reachability-bound on a given program control location directly or path-sensitively.
For the same reason, they also lose the \emph{reachability} perspective of the \emph{reachability-bound}.

\paragraph{Proposed Method.}
To overcome these limitations, 
we design
our algorithm
over the abstract transition graph and effectively uses the \emph{amortized complexity analysis} and \emph{loop summarization-based multipath refinement} techniques in the first step.
In this way, the new algorithm firstly mitigates the limitations faced by each technique individually. 
Then, we introduce two novel quantities,
the \emph{path reachability-bound} and \emph{loop reachability-bound}.
They are the main novelty of our new path-sensitive reachability-bound algorithm built on traditional methods.
The first one bounds the evaluation times of each loop-free and interleave-free path in a refined program, and the second one bounds the number of iterations of an outer loop w.r.t. an inner loop, counting only the iterations when the inner loop is ``entered''. 
We present algorithms for estimating these two quantities. By using them we can then 
%Section~\ref{sec:looprb} and~\ref{sec:pathrb} 
compute the \emph{reachability-bound} for each program point in a path-sensitive way.
To this end, our new methodology studies both the \emph{reachability} and the \emph{quantitative} perspectives and
analyzes the \emph{reachability-bound} in a higher granularity.
