The first one is the \emph{adaptivity rounds} of the programs in adaptive data analysis, where the choice queries asked by data analysts may depend on the results of previous queries. If we represent these interactions in adaptive data analysis as a program, we can find some dependence relations of queries such that some queries may rely on the previous queries.
During these dependence relations, the \emph{adaptivity round} is intuitively defined as the depth of the chain of dependent queries. 
Reasoning about adaptivity is useful in controlling the generalization error of adaptive data analysis, which usually propagates sharply along with the chain. 
Many researchers have found that the generalization error can be controlled well by choosing the appropriate statistic technique according to the adaptivity.
Nevertheless, the adaptivity is not always clear to data analysts when they need it. 
To solve this dilemma, we present a program analysis algorithm based on dependency graphs,
to provide an upper bound on adaptivity to assist data analysts.
This part is developed by first defining the \emph{adaptivity} for 
the adaptive data analysis
and then designing
a program analysis framework for estimating the \emph{adaptivity}. 

As a continuation of the previous problem to get a precise bound when estimating the \emph{adaptivity},
we look at the program's reachability-bound as the second quantitative reachability property.
This property is a worst-case bound on the number of times a given control location 
inside a procedure is visited during the program execution.
This execution property has broad
applications in analyzing other program property beyond quantitative reachability.
For example in the resource cost analysis, this quantitative reachability property
can help to provide a tighter
bound on the resources consumed by a program such as time, memory,
network traffic, power, etc.
In estimating some quantitative property
in the data analysis area, for example, when analyzing the program's \emph{adaptivity}
as introduced above, % on the adaptive data analysis program's \emph{adaptivity}
the reachability-bound on each program control location
can improve the precision of the estimated bound.
In the security analysis area, this reachability-bound helps to improve the accuracy
in estimating the program's information leakage or uncertainty propagation, etc.
Many works in the program analysis area develop algorithms estimating the program's loop bound or overall complexity.
However, there isn't a general analysis algorithm that solves this problem directly or path-sensitively and 
computing a tight reachability-bound for a given program control location is challenging.
Many works in the program analysis area develop algorithms estimating the program's loop bound or overall complexity.
But there isn't a general analysis algorithm that
computes the reachability-bound
directly or path-sensitively.
To leverage these limitations,
we present a path-sensitive reachability-bound algorithm
aiming to find a precise symbolic worst-case reachability-bound on the program's every control location in this paper.
Our algorithm brings together two techniques:
\begin{itemize}
\item 1. ranking function based amortized bound analysis through program abstraction, and
\item 2. loop summarization based multiple loop paths refinement
\end{itemize}
and combines them effectively. 
The effective combination improves the precision of the estimated reachability-bound comparing to adopt either one of them.
It allows us to compute precise reachability-bound on each program point path-sensitively.
We implement a prototype and report on an experimental comparison with state-of-art tools over four different benchmarks.
