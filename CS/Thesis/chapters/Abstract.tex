\begin{abstractpage}
    Program analysis studies the execution behaviors of computer programs
    including programs' safety behavior, privacy behavior, resource usage, etc.
    % Program analysis, for example, on the resource usage of a computer program involves analyzing whether a piece of code consumes certain resources and how many resources are used by this piece of code.
    When program analysis is performed on the resource usage of a computer program,
    one usually analyzes whether a piece of code consumes a certain resource and how much resource is used by this piece of code.
    Program analysis of a program's safety behavior involves analyzing
    if a particular line of code leaks a secret and how much secret is leaked by this line of code. 
    Yet another use of program analysis is studying the program privacy by analyzing
    % In terms of privacy, we analyze 
    whether a specific private data is dependent on other data and how many times they are dependent during multiple executions.
    We notice that when analyzing the aforementioned behaviors of a computer program, there are two dominant perspectives
    shared by them -- ``How Much'' and ``Whether''.
    We refer to the two perspectives as 
    two sub-properties of these program behaviors namely \emph{quantitative} property and \emph{reachability} property.
    For the class of behaviors that share these two sub-properties, we refer to them as \emph{quantitative-reachability} hyper-properties.
    Most existing program analysis methods can analyze only one sub-property of a 
    \emph{quantitative-reachability} hyper-property.
    % from one perspective. 
    These methods are not enough to capture all the different perspectives of it.
    % through different perspectives.
    For example, the reachability analysis methods only tell us whether some code pieces are executed, whether the confidential data is leaked, whether certain data relies on another data, etc., which are only the \emph{reachability} sub-properties.
    These analysis methods do not address how many times or how long these properties hold with respect to some particular code or data. 
    Quantitative analysis methods, such as program complexity analysis, resource cost analysis, execution time estimation, etc. only tell us the upper bound on the overall quantity, i.e., the \emph{quantitative} sub-property.
    However, these quantities are not associated with 
    % any \emph{reachability} sub-property,
    a specific piece of code, program location, private data, etc., which are related to the \emph{reachability} sub-properties.
    This thesis presents new program analysis algorithms for analyzing two representative \emph{quantitative-reachability} hyper-properties.
    Our new analysis methods leverage the limitations in both reachability analysis methods and 
    quantitative analysis methods and
    help to control the program's execution behaviors in higher granularity. 
    We also show the effectiveness of the new analysis algorithms through prototype implementations and experimental evaluations.
    % two representative \emph{quantitative-reachability} hyper-properties. 
    
    
    
    The first noteworthy property we look into is the \emph{adaptivity} rounds in adaptive data analysis. An adaptive data analysis is usually composed of multiple queries among which the choice of some queries may depend on previous queries' results.
    These queries form dependent relations with each other and the
    \emph{adaptivity} is intuitively the depth of these dependence relations.
    Reasoning about \emph{adaptivity} is useful in controlling the generalization error of adaptive data analysis, which usually propagates sharply along with the dependency chain.
    Researchers in the data analysis area have found that the generalization error can be controlled well by choosing the appropriate statistic technique according to the \emph{adaptivity}.
    Nevertheless, adaptivity is not always clear to data analysts when they need it.
    To solve this dilemma, we present a program analysis framework that analyzes this intuitive concept in
    the principle of programming language.
    We first formalize the \emph{adaptivity} through a semantics-based definition.
    Then we present a \emph{quantitative-reachability} analysis algorithm
    % that integrates the \emph{quantitative-reachability} and \emph{quantitative} analysis techniques,
    which estimates a sound upper bound on the adaptivity of the program that implements an adaptive data analysis. 
    
    As a continuation of the previous work, to get a more precise bound on a data analysis program's \emph{adaptivity}, we look at the second \emph{quantitative-reachability} hyper-property -- the number of times a given control location inside a procedure is visited during the program execution.
    The upper bound on this hyper-property is referred to as the \emph{reachability-bound}.
    It can help to improve the program analysis results when studying other different program features.
    % beyond itself.
    For example, the \emph{reachability-bound} on each program location can be used by resource cost analysis to compute a tighter bound on a program's worst-case resource cost.
    % on a program's resource cost.
    % analysis to compute a tighter bound, 
    The accuracy of the adaptivity analysis algorithm presented in part I can also be improved through a tight \emph{reachability-bound} on every program location.
    % , the information leakage, etc. 
    Some existing program complexity analysis methods can be repurposed to analyze and estimate a \emph{reachability-bound}.
    However, these methods focus only on the overall quantity and ignore the path sensitivity in the program.
    For this reason, the \emph{reachability-bound}s of the locations in different sub-procedures are usually over-approximated. 
    As far as we know, there is no general analysis algorithm that computes the reachability-bound for every program location directly and path-sensitively. 
    To this end, we present a path-sensitive reachability-bound algorithm.
    In comparison with previous works, our algorithm is the first one to exploit the path sensitivity to compute a precise reachability-bound for every program location.
    By doing this, we bring together two techniques from resource analysis: 1. amortized bound analysis through program abstraction and ranking function estimation, and 2. summarization-based multiple loop paths refinement.
    Building on this combination, we focus on two new quantities, \emph{path reachability-bound} and \emph{loop reachability-bound}, which allow us to leverage the precision and efficiency of the two techniques, and compute precise reachability-bounds for each program point in a path-sensitive way.
    We implemented our algorithm in a prototype, and we report on an experimental comparison with state-of-art tools over four different sets of benchmarks.
