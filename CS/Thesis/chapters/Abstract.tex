\begin{abstractpage}
Program analysis analyzes the behaviors of a computer program, such as
the resource usage where people analyzes
whether a piece of code consumes certain resources, 
and how much certain resource is used by a program / certain pieces of code,
the data dependency property where people analyzes
whether certain data depends on others, and how many times certain data is dependent during multiple-executions,
safety property where we care
whether certain piece of code leaks a secret,
and how much secret is leaked by a program / some pieces of code?
% As a high level view of the properties mentioned above,
They all share the same two sub-properties, "How Much" and "Whether" from two perspectives.
We refer to the two perspectives as \emph{quantitative} and \emph{reachability}, and we name this class of properties as \emph{quantitative-reachability} property.
Existing analysis from one perspective is not precise enough to capture these properties,
for example, reachability analysis only tells us whether the output relies on user input, whether the secret data is leaked,
whether some pieces of code are executed, etc.
% Reachability can tell us the existence of these properties.
but not how many times or how long these properties hold for programs.
The quantitative analysis such as program complexity and cost analysis only tell us the upper bound on the overall worst case quantity but not where the resource is cost, where the data is leaked, etc.
%
To control program's execution behavior in a higher granularity,
this thesis presents algorithms that complement two lines of techniques effectively and shows its effectiveness in
%  is leaked, which is also crucial in security. 
analyzing two representative \emph{quantitative-reachability} properties.

The first significant property we look into is the \emph{adaptivity rounds} of the programs in adaptive data analysis, which is composed of multiple queries asked by data analysts. Among these queries, the choice of some queries may depend on the results of previous queries, and they form some dependence relations between each other.
% If we represent these interactions in adaptive data analysis as a program, we can find some dependence relations of queries such that some queries may rely on the previous queries.
During these dependence relations, the \emph{adaptivity} is intuitively the depth of the chain of dependent queries. 
Reasoning about adaptivity is useful in controlling the generalization error of adaptive data analysis, which usually propagates sharply along with the dependency chain. 
Researchers in data analysis area have found that the generalization error can be controlled well by choosing the appropriate statistic technique according to the \emph{adaptivity}.
Nevertheless, the \emph{adaptivity} is not always clear to data analysts when they need it. 
To solve this dilemma, we present a program analysis algorithm based on dependency graphs,
to provide an upper bound on adaptivity to assist data analysts.
We first define the \emph{adaptivity} in a formal semantics model,
and then design
a program analysis framework combining the dependency analysis and quantitative analysis techniques for statically estimating the \emph{adaptivity}. 

As a continuation of the previous problem, to get a more precise bound on the \emph{adaptivity},
we look at the second \emph{quantitative-reachability} property -- 
the number of times a given control location 
inside a procedure is visited during the program execution.
The upper bound on this execution number for 
a given control location is referred to as the \emph{reachability-bound} by~\cite{GulwaniZ10} in the first place.
A tight reachability-bound
can help to improve the analysis result on other program features such as the resource cost, the \emph{adaptivity} of data analysis programs, the information leakage in security analysis area, etc.
% For example, in the resource cost analysis, this \emph{quantitative-reachability} property
% can help to provide a tighter
% bound on the resources consumed by a program such as time, memory,
% network traffic, power, etc.
% In the data analysis area,

% In security, this reachability-bound helps to improve the accuracy

Though there are many program analysis algorithms estimates the program's loop bound or overall complexity, there isn't a general analysis algorithm that solves \emph{reachability-bound} for each program location directly or path-sensitively.
Moreover, computing a tight reachability-bound for a given program control location is challenging.
% Many works in the program analysis area develop algorithms estimating the program's loop bound or overall complexity.
% But there isn't a general analysis algorithm that
% computes the reachability-bound
% directly or path-sensitively.
To leverage these limitations,
we present a path-sensitive reachability-bound algorithm
aiming to find a precise symbolic reachability-bound on the program's every control location.
%  in this paper.
Our algorithm brings together two techniques: 1. the ranking function based amortized bound analysis through program abstraction, and 2. the loop summarization based multiple loop paths refinement,
% \begin{itemize}
% \item 1. ranking function based amortized bound analysis through program abstraction, and
% \item 2. loop summarization based multiple loop paths refinement
% \end{itemize}
and combines them effectively. 
The effective combination improves the precision of the estimated reachability-bound comparing to apply either one of them.
% It allows us to compute precise reachability-bound on each program point path-sensitively.
We implement a prototype and report on an experimental comparison with state-of-art tools over four different benchmarks.
