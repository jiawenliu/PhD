We are interested in defining a notion of dependencies between program variables since assigned variables are a good proxy to study dependencies between queries--- we can recover query requests from variables associated with queries. We consider dependencies that can be generated by either data or control flow.
% as follows,
% \begin{enumerate}
For example, in the program 
\[c_1 =[\assign{x}{\query(\chi[2])}]^1 ;[\assign{y}{\query(\chi[3] + x)}]^2\]
the query $\query(\chi[3] + x)$ depends on the query $\query(\chi[2]))$ through a \emph{value dependency} via $x^1$. Although $x$ is not directly used as the index of $\chi$ for accessing a certain column, we still claim there is a value dependency between
these two queries.
\\
Conversely, in the program
\[c_2 = [\assign{x}{\query(\chi[1])}]^1 ; \eif( [x > 2]^2 , [\assign{y}{\query(\chi[2])}]^3, [\eskip]^4 )\] 
the query $\query(\chi[2])$ 
depends on the query $\query(\chi[1])$ via the \emph{control dependency} of the guard of the if command involving the labeled variable $x^1$.
Our running example does not have if control in the while body, while we have examples in Section~\ref{sec:adapt-example} showing the \emph{control dependency} between queries.

To define the dependency relation between program variables we will consider two events that are generated from the same command, hence they have the same variable name / boolean expression and label but have either different values or different query expressions, captured by the following definition. 

\begin{defn}[Events Different in the Value]
\label{def:diff}
Two events $\event_1, \event_2 \in \eventset$ differ in their value, or query value,
denoted as $\diff(\event_1, \event_2)$, if and only if:
{\small
\begin{subequations}
\begin{align}
& \pi_1(\event_1) = \pi_1(\event_2) 
 \land 
 \pi_2(\event_1) = \pi_2(\event_2) \\
& 
\begin{array}{l}
 \land 
 \Big(
 \big(\pi_{4}(\event_1) = \pi_{4}(\event_2) = \bullet 
 \land 
 \pi_3(\event_1) \neq \pi_3(\event_2)
 \big)
 \\ \qquad \lor 
 \big(\pi_4(\event_1) \neq \bullet
 \land 
 \pi_4(\event_2) \neq \bullet
 \land 
 \pi_{4}(\event_1) \neq_q \pi_{4}(\event_2)
 \big ) 
 \Big).
\end{array}
\end{align}
\label{eq:diff}
\end{subequations}
}
% where $\qexpr_1 =_{q} \qexpr_2$ denotes the semantics equivalence between query values
% % \footnote{The formal definition is in the supplementary material},
% and $\pi_i$ projects the $i^{th}$ element from the quadruple of an event.
\end{defn}
Intuitively, the \emph{event differ in value} is a partial negation of the \emph{event equivalence} in Definition~\ref{def:event_eq}.
Equation~\ref{eq:diff}(a) is the same as the first line in Equation~\ref{eq:event_eq}.
In Equation~\ref{eq:diff}(b), when the event corresponded to a query request, we require the query value in the fourth element to be different regarding the \emph{query equivalence} definition, which is opposite to the last line in Equation~\ref{eq:event_eq}.

Specifically, we first look at the first two elements of two events,
as in Equation~\ref{eq:diff}(a).
The conjunction $\pi_1(\event_1) = \pi_1(\event_2) 
 \land 
 \pi_2(\event_1) = \pi_2(\event_2)$ 
requires that $\event_1$ and $\event_2$ have the same variable name and label. 
This guarantees that $\event_1$ and $\event_2$ are generated from the same labeled command.
In Equation~\ref{eq:diff}(b),
two kinds of comparisons between the third and fourth elements are for the non-query assignment and query request separately.
For events generated from the non-query assignments 
($\pi_{4}(\event_1) =_q \pi_{4}(\event_2) = \bullet$), we only compare their assigned values through $\pi_3(\event_1) \neq \pi_3(\event_2)$.
However, for the events from query requests 
($\pi_{4}(\event_1) \neq \bullet \land \pi_{4}(\event_2) \neq \bullet$),
we are comparing their query value in the $4^{th}$ location via $\pi_{4}(\event_1) \neq_q \pi_{4}(\event_2)$ rather than the answer computed from the unknown database and unknown mechanism in the $3^{rd}$ element.
Through this way, when looking into the dependency relation between queries, we are able to check whether the ``choice'' of a query request is affected by others.

\textbf{Example.}
I want to highlight that if two events are both generated from query requests, we are not comparing their query answer in the third position of the event, but the query value in the fourth position.
For example, two events $\event_1 = (x, 1, 0, \chi[0]+1)$ and $\event_2 = (x, 1, 0, \chi[1] + 1)$ are different by our different even though $\pi_3(\event_1) = \pi_3(\event_2)$.
We compare only the forth element where $ \chi[0]+1 \neq_q \chi[1] + 1$ by Definition~\ref{def:query_equal}.
The Equation~\ref{eq:diff}(b) capture this by first checking
$\pi_4(\event_1) \neq \bullet \land \pi_4(\event_1) \neq \bullet$ to guarantee
both events are from query request.
Then we check again the forth element $\pi_4(\event_1) \neq_1 \pi_4(\event_2) \neq \bullet$ to guarantee
that the two events sent different query requests.

The operator $\tlabel : \tdom \to (\mathcal{P}{(\ldom)} \cup \{ \infty \})$ gives the set of labels in every event belonging to 
a trace, whose behavior is defined as follows,
\[
\begin{array}{ll}
    \tlabel{(\trace :: (\_, l, \_, \_)) } \triangleq \{l\} \cup \tlabel{(\trace )} & \text{if}~ \trace \in \ftdom
    \\
    \tlabel{(\trace)} \triangleq \infty & \text{if}~ \trace \in \inftdom
    \\
    \tlabel({[ ]}) \triangleq \{\}
\end{array}
\]

We return $\infty$ if the input trace is an infinite trace.

Then we need to define the dependency relation between events in order to define the \emph{variable may-dependency} relation.
To define the \emph{event may-dependency}, we first introduce the counter notation,
$\vcounter : \tdom \to \mathbb{N} \to \mathbb{N}$ to count the 
occurrence of a label in a trace as below.
% It is used when defining the components on a semantics-based dependency graph.
 \begin{defn}[Counter $\vcounter : \tdom \to \mathbb{N} \to (\mathbb{N}\cup\{\infty\})$]
 \label{def:trace_cnt}
 Given a trace $\trace \in \tdom$ and a label $l$, the occurrence of $l$ in $\trace$ is computed by
 $\vcounter(\trace, l)$ as follows.
 \[
 \begin{array}{ll}
 \vcounter(\trace :: (\_, l, \_, \_), l ) \triangleq \vcounter(\trace, l) + 1
 &
 \vcounter(\trace ::(b, l, v, \bullet), l) \triangleq \vcounter(\trace, l) + 1
 \\
 \vcounter(\trace :: (x, l, v, \qval), l) \triangleq \vcounter(\trace, l) + 1
 &
 % \vcounter(\trace :: (\_, l', \_, \_), l ) \triangleq \vcounter(\trace, l), l' \neq l 
 % &
 \vcounter(\trace :: (x, l', v, \bullet), l) \triangleq \vcounter(\trace, l), l' \neq l
 \\
 \vcounter(\trace :: (b, l', v, \bullet), l) \triangleq \vcounter(\trace, l), l' \neq l
 &
 \vcounter(\trace :: (x, l', v, \qval), l) \triangleq \vcounter(\trace, l), l' \neq l
 \\
 \vcounter({[]}, l) \triangleq 0
 &
 \vcounter(\trace, l) \triangleq \infty ~ \text{if}~ \trace \in \inftdom
 \end{array}
 \]
\end{defn}
Again, we still return $\infty$ if the input trace is an infinite trace.

\begin{defn}[Boolean Event Negation]
 \label{def:adapt_boolevent_neg}
 For a testing event, we define its negation operation as follows,
 \[
 \forall \event \in \eventset^{\test}, \bexpr \in \booldom, l \in \ldom,
 v \in \{\etrue, \efalse\} \sthat 
 \event = (\bexpr, l, v, \bullet) \implies
 \neg\event = (\bexpr, l, \neg v, \bullet)\]
\end{defn}

We can now define when an event \emph{may depend} on another one.
\begin{defn}[Event May-dependency]
\label{def:event_dep}
An event $\event_2$ is in the \emph{event may-dependency} relation with an assignment event $\event_1 \in \eventset^{\asn}$ in a program ${c}$ 
with a hidden database $D$ and 
with a witness trace $\trace \in \ftdom$,
$\eventdep(\event_1, \event_2, [\event_1] \tracecat \trace \tracecat [\event_2], c, D)$ if and only if
\begin{subequations}
\begin{align}
 & 
 \exists \trace_0, \trace_1, \trace' \in \ftdom,\event_1' \in \eventset^{\asn}, {c}_1, {c}_2 \in \cdom \sthat \diff(\event_1, \event_1') \land \\
 & 
 \quad (\exists \event_2' \in \eventset \sthat
 \left(
 \begin{array}{l} 
 \config{{c}, \trace_0} \rightarrow^{*} 
 \config{{c}_1, \trace_1 \tracecat [\event_1]} \rightarrow^{*} 
 \config{{c}_2, \trace_1 \tracecat [\event_1] \tracecat \trace \tracecat [\event_2] } 
 \\ 
 \quad \land
 \config{{c}_1, \trace_1 \tracecat [\event_1']} \rightarrow^{*}
 \config{{c}_2, \trace_1 \tracecat[ \event_1'] \tracecat \trace' \tracecat [\event_2'] } 
 \\
 \quad \land
 \diff(\event_2,\event_2' ) \land 
 \vcounter(\trace, \pi_2(\event_2))
 = 
 \vcounter(\trace', \pi_2(\event_2'))\\
 \end{array}
 \right)\\ 
 & 
 \quad
 \lor 
 \left(
 \begin{array}{l} 
 \exists \trace_3, \trace_3' \in \ftdom, \event_b \in \eventset^{\test} \sthat 
 \\
 \quad \config{{c}, \trace_0} \rightarrow^{*} \config{{c}_1, \trace_1 \tracecat [\event_1]} \rightarrow^{*}
 \config{c_2, \trace_1 \tracecat [\event_1] \tracecat
 \trace \tracecat [\event_b] \tracecat \trace_3} 
 \\ \quad \land
 \config{{c}_1, \trace_1 \tracecat [\event_1']} \rightarrow^{*} 
 \config{c_2, \trace_1 \tracecat [\event_1'] \tracecat \trace' \tracecat [(\neg \event_b)] \tracecat \trace_3'} 
 \\
 \quad \land \tlabel({\trace_3}) \cap \tlabel({\trace_3'})
 = \emptyset
 \land \vcounter(\trace', \pi_2(\event_b)) = \vcounter(\trace, \pi_2(\event_b)) 
 \land \event_2 \in \trace_3
 \land \event_2 \not\in \trace_3'
 \end{array}
 \right)
 ),
\end{align}
\label{eq:eventdep}
\end{subequations}
% where $\tlabel(\trace) \subseteq \ldom$ is the set of the labels in all the events from trace $\trace$ and $\event_2 \in \trace_3$ or $\event_2 \notin \trace_3$ denotes that $\event_2$ belongs to $\trace_3$ or not.
\end{defn}
The first line in Equation~\ref{eq:eventdep}(a) requires that $\event_1$ comes from an assignment command.
Then, $\diff(\event_1, \event_1')$ guarantees that value assigned to the same variable is different in $\event_1'$.

The following two parts in Equation~\ref{eq:eventdep}(b) and (c) capture the value dependency and control dependency respectively. 
As in the literature on non-interference, and following~\cite{Cousot19a}, we formulate these dependencies as relational properties, i.e. in terms of two different traces of execution. 
I force these two traces to differ by using the event $\event_1$ in one and $\event_1'$ in the other. 
Both Equation~\ref{eq:eventdep}(b) and (c) execute the program two times w.r.t. the different values in $\event_1$ (as line:1 in Equation~\ref{eq:eventdep}(b) and line:2 in Equation~\ref{eq:eventdep}(c))
and $\event_1'$ (as line:2 in Equation~\ref{eq:eventdep}(b) and line:3 in Equation~\ref{eq:eventdep}(c)).
However, the definition checks the difference in the newly generated traces in different ways in line:3 of Equation~\ref{eq:eventdep}(b) and line:4 of Equation~\ref{eq:eventdep}(c) to capture the value dependency and control dependency respectively.
This idea is similar to the semantics dependency definition from~\cite{Cousot19a}.

For the value dependency, we check whether the change of $\event_1$ also creates a change in the value of $\event_2$ or not.
In Equation~\ref{eq:eventdep}(b) line:2, if the newly generated trace, $\trace' ++ [\event_2']$ still contains $\event_2$ as $\event_2'$, I check the difference on their value in line:3.
We additionally check whether the two events appear the same times in the two traces.
This is to make sure that they are in the same iteration if the two events are generated from the command of a loop body.
If they only differ in their assigned values, i.e., $\diff(\event_2, \event_2')$ and
they are in the same loop iteration (via $\vcounter(\trace, \pi_2(\event_2)) = \vcounter(\trace', \pi_2(\event_2'))$),
then we define there is a value \emph{may-dependency} relation between $\event_1$ and $\event_2$.

The Equation~\ref{eq:eventdep}(c) captures the control dependency through observing whether $\event_2$ is disappeared from the second execution traces, $\trace' \tracecat [(\neg \event_b)] \tracecat \trace_3'$ in line:3.
$\event_2 \in \trace_3 \land \event_2 \not\in \trace_3'$ in Equation~\ref{eq:eventdep}(c) line:4 specifies this disappearance.
$\vcounter(\trace', \pi_2(\event_b)) = \vcounter(\trace, \pi_2(\event_b))$ is used to make sure the two executions are
in the same loop iteration as well.
Different from Equation~\ref{eq:eventdep}(b) line:3,
I use a testing event, $\event_b$ here because checking only $\event_2$'s occurrence and the
$\vcounter(\trace, \pi_2(\event_2)) = \vcounter(\trace', \pi_2(\event_2'))$
causes false positives
when there is no influence through control dependency. 
For example in the following program
\[
 \clabel{\assign{i}{3}}^{0}; \clabel{\assign{x}{\query(\chi[0])}}^1 \ewhile \clabel{i \geq 0}^{2} \edo ( \clabel{\assign{y}{\query(\chi[i])}}^3; \clabel{\assign{i}{ i - 1}}^{4})
\]
we execute only two iterations of the while loop as follows,
\[
 \begin{array}{l}
 \config{
 \clabel{\assign{i}{3}}^{0}; \clabel{\assign{x}{\query(\chi[0])}}^1; \ewhile \clabel{i \geq 0}^{2} \edo ( \clabel{\assign{y}{\query(\chi[i])}}^3; \clabel{\assign{i}{ i - 1}}^{4}), \trace_0} \\
 \rightarrow^{*} \config{\ewhile \clabel{i \geq 0}^{2} \edo ( \clabel{\assign{y}{\query(\chi[i])}}^3; \clabel{\assign{i}{ i - 1}}^{4}), \trace_1 \tracecat [(x, 1, v, \chi[0])]} \\
 \rightarrow^{*}
 \config{\ewhile \clabel{i \geq 0}^{2} \edo ( \clabel{\assign{y}{\query(\chi[i])}}^3; \clabel{\assign{i}{ i - 1}}^{4}), 
 \\ \qquad \quad \trace_1 \tracecat [(x, 1, v, \chi[0]), (i \geq 0, 2, \etrue, \bullet), (y, 3, v_0, \chi[0]), (i, 4, 1, \bullet), (i \geq 0, 2, \etrue, \bullet)]
 \\ \qquad \quad \tracecat [ (y, 3, v_1, \chi[1]) ]}.
 \end{array} 
\]
To find the dependency relation between $(x, 1, v, \chi[0])$ and $(y, 3, v_1, \chi[1])$, we modify the first event and then execute only the first iteration of the while loop as follows,
\[
 \begin{array}{l}
 \config{\ewhile \clabel{i \geq 0}^{2} \edo ( \clabel{\assign{y}{\query(\chi[i])}}^3; \clabel{\assign{i}{ i - 1}}^{4}), \trace_1 \tracecat [(x, 1, v', \chi[0])]} \\
 \rightarrow^{*}
 \config{\ewhile \clabel{i \geq 0}^{2} \edo ( \clabel{\assign{y}{\query(\chi[i])}}^3; \clabel{\assign{i}{ i - 1}}^{4}),
 \\ \qquad \quad \trace_1 \tracecat [(x, 1, v', \chi[0]), (i \geq 0, 2, \etrue, \bullet), (y, 3, v_1, \chi[0])] 
 \\ \qquad \quad \tracecat[]}.
 \end{array} 
 \]
Without looking into a testing event, we can always say $(y, 3, v_1, \chi[1]) \not\in []$ and they have event may-dependency relation.
However, there does not exist any dependency relation between $(x, 1, v, \chi[0])$ and $(y, 3, v_1, \chi[1])$.
For this reason, we use the presence of a test event whose value is affected by the change in $\event_1$
to guarantee that the influence goes through a control flow in the first step.
Because the control dependency can only be passed through the guard of if or while command, this guard must be evaluated into two different values ($\event_b$ and $\neg \event_b$) in the two executions.

I show the following three examples to illustrate the event may-dependency relation. 

\textbf{Example I.} In the first example, we have two assignment commands and the second one is a query request.
\[
 \clabel{\assign{x}{1}}^0;\clabel{\assign{y}{\query(\chi[x]) \times \chi[0]}}^1.
\]
I want to highlight in this example, the dependency relation is defined by analyzing whether the ``choice'' of the query request is affected but not the ``answer'' of the query request.
With an arbitrary initial trace, execution of this program generates two events $\event_1 = (x, 0, 1, \bullet)$ and $\event_2 = (y, 1, v, \chi[1] \times \chi[0])$
and the witness execution trace $[(x, 0, 1, \bullet), (y, 1, v, \chi[1] \times \chi[0])]$,
where $v = \query(\chi[1] \times \chi[0])$ is the query answer computed by an unknown mechanism using a hidden database.
By Definition~\ref{def:event_dep}, we modify the value assigned to $x$ into $0$ and execute the second command.
Then we have another execution trace 
$[(x, 0, 0, \bullet), (y, 1, v', \chi[0] \times \chi[0])]$.
Since $\event_2' = (y, 1, v', \chi[0] \times \chi[0])$ and $\chi[0] \times \chi[0] \neq_q \chi[1] \times \chi[0]$
by Definition~\ref{def:query_equal}.
Then there is an event may-dependency relation, $\eventdep(\event_1, \event_2, [(x, 0, 1, \bullet), (y, 1, 0, \chi[1] \times \chi[0])], c, D)$.

\textbf{Example II.} In the following example similar to the previous one, the second query request is $\clabel{\assign{y}{\query(\chi[x]) \times 0}}^1$.
\[
 \clabel{\assign{x}{1}}^0;\clabel{\assign{y}{\query(\chi[x]) \times 0}}^1
\]
Now with a similar witness execution trace $[(x, 0, 1, \bullet), (y, 1, v, \chi[1] \times 0)]$ and two events $\event_1 = (x, 0, 1, \bullet)$ and $\event_2 = (y, 1, v, \chi[1] \times 0)$
where $v = \query(\chi[1] \times 0)$ is the query answer computed by an unknown mechanism using a hidden database,
we cannot find any $\event_1'$ that affect the choice of $\event_2$.
Because for any value $v$ where $\event_1' = (x, 0, v, \bullet)$,
we always have the execution trace $[(x, 0, v, \bullet), (y, 1, v', \chi[v] \times 0)]$ and
have $\chi[v] \times 0 =_q \chi[1] \times 0$ by Definition~\ref{def:query_equal}.
So $\event_1$ and $\event_2$ are not in this event may-dependency relation in this definition.

\textbf{Example III.} The last example has an if command.
\[
 \clabel{\assign{x}{\query(\chi[1] \emax 1 )}}^0;
 \eif (\clabel{0 < x}^1, \clabel{\assign{y}{\query(\chi[2])}}^2, \clabel{\eskip}^3)
\]
Since the mechanism and the hidden database are unknown, the answer of the first query request $\clabel{\assign{x}{\query(\chi[1] \emax 1 )}}^0$, could be different.
Also, the answer of the first query in $x$ is used in the guard of the if command,
which
% and 
% $x$ smaller than $0$ or not 
decides whether the second query request $\clabel{\assign{y}{\query(x) \times 0}}^2$ is executed.
In this sense, intuitively the choice of the second query 
request command is affected by
the answer to the first one.
This definition captures this dependency through a witness execution trace
$[(x, 0, v, \chi[1] \emax 1), (0 > x, 1, \etrue, \bullet), (y, 2, v', \chi[2])]$ and
two events 
$\event_1 = (x, 0, v, \chi[1] \emax 1) $ and $\event_2 = (y, 2, v', \chi[2])$ by taking $v> 0$.
Then by modifying $\event_1 $ into $(x, 0, 0, \chi[1] \emax 1)$,
there is another execution trace $[(x, 0, v, \chi[1] \emax 1), (0 > x, 1, \efalse, \bullet)]$.
Since $\event_2 $ disappeared in the second execution trace,
our event may-dependency definition captures this dependency relation.

 
We can now extend the dependency relation to variables by considering all the assignment events generated during the program's execution. 

\begin{defn}[Variable May-dependency]
 \label{def:var_dep}
A variable ${x}_2^{l_2} \in \lvar(c)$ \emph{may-depend} on the 
 variable ${x}_1^{l_1} \in \lvar(c)$ in a program ${c}$,
 %
 $\vardep({x}_1^{l_1}, {x}_2^{l_2}, {c})$, if and only if
\begin{center}
$
{
\begin{array}{l}
\exists \event_1, \event_2 \in \eventset^{\asn}, \trace \in \ftdom \sthat
\pi_{1}{(\event_1)}^{\pi_{2}{(\event_1)}} = {x}_1^{l_1}
\land
\pi_{1}{(\event_2)}^{\pi_{2}{(\event_2)}} = {x}_2^{l_2}% \\ \quad 
\land 
\eventdep(\event_1, \event_2, \trace, c) 
 \end{array}
}%
$
\end{center}
 \end{defn}
From the definition, a labeled variable $x_2^{l_2}$ may depend on another labeled variable $x_1^{l_1}$ in a program $c$, 
as long as there exist two assignment events $\event_1$ (for $x_1^{l_1}$) and $\event_2$ for $x_2^{l_2}$
satisfy the \emph{event may-dependency} relation under a witness trace $\trace$. 
Notice that in the definition above I can also have that the two variables are the same,
this allows us to capture self-dependencies.

\textbf{Example I.}
Below is an example to better understand this definition.
\[
 \clabel{\assign{x}{0}}^0;\clabel{\assign{y}{x}}^1.
\]
In this example, we have two assignment commands without query requests as follows. 
Intuitively, a result of the first command is always $0$, and the same for the second command,
and the second command depends on the constant $0$ rather than variable $x$.
However, I aim to capture the dependency 
relation passing through variables, so there is still a variable may-dependency relation between the two labeled
variable $x^0$ and $y^1$.
Specifically,
execution of this program with arbitrary initial trace generates two events $\event_1 = (x, 0, 0, \bullet)$ and $\event_2 = (y, 0, 0, \bullet)$.
Then we can have the witness execution trace be $[(x, 0, 0, \bullet), (y, 1, 0, \bullet)]$ and 
modify the value assigned to $x$ into $1$.
Continuously executing the second assignment command gives us another execution trace 
$[(x, 0, 1, \bullet), (y, 1, 1, \bullet)]$.
Now we have $\event_2' = (y, 1, 1, \bullet)$ and $\diff(\event_2, \event_2')$ by Definition~\ref{def:diff}.
Then there is an event may-dependency relation between $\event_1$ and $\event_2$ by Definition~\ref{def:event_dep}.
