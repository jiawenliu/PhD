We can now define the \emph{semantics-based dependency graph} for a well-formed program $c$. We want this graph to carry both quantitative perspective information and the reachability perspective (via dependency) information. 

There are some notations we want to remind.
The labeled variables of $c$,
$\lvar(c) \subseteq \mathcal{LV}$ contains all the variables in $c$'s assignment commands, with the command labels as superscripts. 
The set of query-associated variables (in query request assignments),
$\qvar(c) \subseteq \lvar(c)$ contains all labeled variables in $c$'s query requests. Both of them are defined in Section~\ref{sec:language-syntax} in Definition~\ref{def:lvar} and~\ref{def:qvar}.
% The set of initial traces of $c$,
% $\ftdom_0(c) \subseteq \ftdom$
% contains all the initial trace of $c$.
% Each initial trace,  $\trace_0 \in \ftdom_0(c)$ contains the initial values of all input variables of $c$. 
% For instance, the initial trace of $\kw{twoRounds(k)}$ example contains the initial value of the input variable $k$.

We define \emph{counter} $\vcounter : \tdom \to \mathbb{N} \to \mathbb{N}$ to count the 
occurrence of a label in a trace as below. It is used when define the components on a semantics-based dependency graph.

  \begin{defn}[Counter $\vcounter : \tdom \to \mathbb{N} \to (\mathbb{N}\cup\{\infty\})$]
    \label{def:trace_cnt}
    Given a trace $\trace \in \tdom$ and a label $l$, the occurrence of $l$ in $\trace$ is computed by
    $\vcounter(\trace, l)$ as follows.
    \[
      \begin{array}{ll}
      \vcounter(\trace :: (\_, l, \_, \_), l ) \triangleq \vcounter(\trace, l) + 1
      &
      \vcounter(\trace  ::(b, l, v, \bullet), l) \triangleq \vcounter(\trace, l) + 1
      \\
      \vcounter(\trace  :: (x, l, v, \qval), l) \triangleq \vcounter(\trace, l) + 1
      &
      % \vcounter(\trace :: (\_, l', \_, \_), l ) \triangleq \vcounter(\trace, l), l' \neq l 
      % &
      \vcounter(\trace  :: (x, l', v, \bullet), l) \triangleq \vcounter(\trace, l), l' \neq l
      \\
      \vcounter(\trace  :: (b, l', v, \bullet), l) \triangleq \vcounter(\trace, l), l' \neq l
      &
      \vcounter(\trace  :: (x, l', v, \qval), l) \triangleq \vcounter(\trace, l), l' \neq l
      \\
      \vcounter({[]}, l) \triangleq 0
      &
      \vcounter(\trace, l) \triangleq \infty ~ \text{if}~ \trace \in \inftdom
      \end{array}
      \]
\end{defn}
\begin{defn}[Semantics-based Dependency Graph]
\label{def:trace_graph}
For a well-formed program ${c} \in \cdom$,
its \emph{semantics-based dependency graph} 
$\traceG({c}) \triangleq (\traceV({c}), \traceE({c}), \traceW({c}), \traceF({c}))$.
Each of the four components is defined as follows,
{\small
\[
\begin{array}{lll}
  \text{Vertices} &
  \traceV({c}) & := \left\{ 
  x^l
  ~ \middle\vert ~ x^l \in \lvar(c)
  \right\}
  \\
  \text{Directed Edges} &
  \traceE({c}) & := 
  \left\{ 
  (x^i, y^j) 
  ~ \middle\vert ~
  x^i, y^j \in \lvar(c) \land \vardep(x^i, y^j, c) 
  \right\}
  \\
  \text{Weights} &
  \traceW({c}) & := 
  \{ 
  (x^l, w) 
  ~ \vert ~ 
  w : \ftdom_0(c) \to \mathbb{N}
  \land
  x^l \in \lvar(c) \land
  \\ & & \qquad 
  \forall \trace_0 \in \ftdom_0(c), \trace' \in \ftdom, l' \sthat 
  \\ & & \qquad 
  \config{{c}, \trace_0} \to^{*} 
  \config{\clabel{\eskip}^{l'}, \trace_0 \tracecat \trace'} 
  \land w(\trace_0) = \vcounter(\trace', l) \}  
  \\
  \text{Query Annotations} &
  \traceF({c}) & := 
  \big\{(x^l, n)  
  ~ \vert ~  x^l \in \lvar(c) 
  \\ & & \qquad
  \land n = 1 \Leftrightarrow x^l \in \qvar(c) \land n = 0 \Leftrightarrow  x^l \notin \qvar(c)
  \big\},
\end{array},
\]
}

% is \emph{well-formed} if and only if $ \{x^l \ |\ (x^l,w)\in \traceW({c})\} = \traceV({c}) $.
\end{defn}


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%% The Explanation of Dependency Graph %%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
There are four components in this graph.
\begin{enumerate}
    \item The vertices $\traceV({c})$ of a program $c$ are all its labeled variables, $\lvar(c)$ which are statically collected.
    \item $\traceF(c)$ contains the \emph{query annotation} for 
    every vertex $x^l \in \traceV(c)$. It indicates whether $x^l$ comes from a query request (1) or not (0) by checking if the labeled variable $x^l$ of the vertex is in $\qvar(c)$.
    \item Edges in $\traceE(c)$ are all directed.
    They are built from the  \emph{variable may-dependency} relation, i.e. $\vardep(x^i, y^j, c)$ in Definition~\ref{def:var_dep} between two labeled variables.
    Intuitively, there is an edge from $x^i$ to $y^j$ if and only if they are in the \emph{variable may-dependency} relation. 
    This is the key definition in order to formalize the intuitive \emph{adaptivity}. We use this to ingredient the \emph{reachability} sub-property of \emph{adaptivity} on this graph.
    \item 
The weight function in $\traceW(c)$ for each vertex (also a labeled variable), $w : \ftdom_0(c) \to \mathbb{N}$
maps from an initial trace $\trace_0 \in \ftdom_0(c)$ to a natural number.
% A weight function $w \in \traceW(c)$ is a function that 
Specifically, for every initial trace $\trace_0 \in \ftdom_0(c)$,
the weight for a labeled variable $x^l$ under this initial trace, $w(\trace_0)$
gives the number of times that the assignment command with the label $l$ is evaluated.
% the corresponding vertex $x^l$ is visited. 
% For each vertex $x^l$, 
In other words, it tracks for each vertex $x^l$ its visiting times 
% (i.e., the evaluation times of the command with the label $l$)
 when the program $c$ is executing under the initial trace $\trace_0$.
 The weight functions are total and with range $\mathbb{N}$. 
 As discussed above in Definition~\ref{def:adaptfun-wfprog}, since a well-formed program $c$ is always terminating, we have
 for any initial trace $\trace_0 \in \ftdom_0(c)$ a terminating execution 
 $\config{{c}, \trace_0} \to^{*} \config{\clabel{\eskip}^{l'}, \trace_0\tracecat\trace'} $
 which produce a finite execution trace $\trace \in \ftdom$.
The visiting times are computed by the counter operator $\vcounter(\trace', l)$
by counting the occurrence of the label $l$ in $\trace'$.
As an instance, in the semantics-based dependency graph of $\kw{twoRounds}$ in Figure~\ref{fig:overview-example}(b), the weight of the vertex $x^3$ is 
$\lambda \trace_0 \sthat \env(\trace_0) k$, i.e.
a function of type $\ftdom_0(\kw{twoRound(k)}) \to \mathbb{N}$.
$\env(\trace_0) k$ fetch the initial value assigned to variable $k$ from the initial trace $\trace_0$.
Specifically, 
% given input $\trace_0$, 
we execute the $\kw{twoRound(k)}$ program under input $\trace_0$ as $\config{\kw{twoRound(k)}, \trace_0} \to^{*} \config{\clabel{\eskip}^{l'}, \trace_0\tracecat\trace'} $.
Then $w_k(\trace_0)$ outputs the occurrence times of the label $3$ in $\trace'$, which is always
the value of $k$ in the initial trace, i.e., $\env(\trace_0) k$.
So we have its weight function $\lambda \trace_0 \sthat \env(\trace_0) k$ always equal to the 
occurrence times of the label $3$ in the execution trace of $\kw{twoRound(k)}$.
% Notice that weight functions are total and with range $\mathbb{N}$. 
% This means that if a program $c$ has some non-terminating behavior, the set $\traceW(c)$ will be empty.
% As discussed above in Definition~\ref{def:adaptfun-wfprog},
% a well-formed program $c$ always terminates when executing under any initial trace $\trace_0 \in \ftdom_0(c)$.
% % only graphs which have a weight for every vertex with the terminating programs. 
% So the set $\traceW(c)$ will not be empty.
\end{enumerate}
The main novelty of  the semantics-based dependency graph is the combination of the quantitative and dependency information. 
It can tell both the dependency between queries via the directed edge, and the times they depend on each other via the weight.
In this sense, this graph captures both quantitative perspective (via weight) and the reachability perspective (via dependency) information for adaptivity. Then we can utilize them, together with the query annotation to precisely define the \emph{adaptivity} concept.
